# ClipFlow

原生 macOS 剪贴板历史工具。默认通过 **Command + `1234567890-=`** 粘贴当前前12条记录；提供 Option 回退、释放全部快捷键和按应用排除。

当前版本为 **0.5.0 开发预览**，尚未完成全部跨应用和连续粘贴验收。仓库包含源码、测试、构建脚本与阶段验证记录。

## 普通用户安装（无需编译）

1. 打开 [GitHub Releases 下载页](https://github.com/lrc839-tech/ClipFlow/releases)，在 **Assets** 下载 **ClipFlow-版本号-macOS-arm64.dmg**。Source code 压缩包是源码，不是安装包。
2. 双击 DMG，把 `ClipFlow.app` 拖到窗口里的 `Applications`（应用程序）文件夹；从 Mac 的应用程序文件夹打开，不要在 DMG 里直接运行。DMG 里同时附有“安装与首次打开说明”HTML和文本文件。
3. **首次打开如果被系统拦截**：先尝试打开一次，关闭拦截提示；打开“系统设置 → 隐私与安全性”，在安全性区域找到 ClipFlow，点击“仍要打开 / Open Anyway”，按要求本人验证身份，再在确认框点击“打开”。不需要反复双击固定次数；若提示未出现，可重新尝试打开一次后返回设置。此流程参考 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。
4. **单独授权输入权限**：到“隐私与安全性 → 辅助功能”（部分系统称“设备控制和数据访问”），添加并启用刚安装的 ClipFlow。退出重开，或点“重试注册”，确认“输入权限已就绪”和“Command接管中：12/12”。“仍要打开”不等于已获得辅助功能权限。
5. 正常 Command+C 复制或 Command+X 剪切内容，先点击目标输入框，再按 Command+1～9、0、-、= 粘贴当前对应记录；从 CF 菜单点选记录会直接粘贴，随后 Command+V 继续粘贴这条。在设置中的历史页点击“移到第1条”，该记录进入快捷键1，后续新复制继续排在它前面。完整流程、更新与排障见 **[安装与首次使用](docs/INSTALL.md)**。

安装包仅适用于 **Apple Silicon（M系列）Mac**，不是 Intel 或 Windows 版本。当前采用临时签名，**尚未完成 Developer ID 签名与 Apple 公证**。若提示“将损坏你的电脑”或“已损坏”，请停止安装并重新下载、核对发布页SHA-256，参照安装说明排障；不要把这类提示一律当作普通未公证提示。安装不要求关闭系统安全保护或执行移除隔离属性的命令。

## 功能

- 菜单栏常驻，关闭管理窗口后继续运行。监听系统剪贴板变化，Command+C复制和Command+X剪切均会收录（以来源实际写入剪贴板为准）。
- SQLite 保存历史索引，独立文件保存原始二进制数据；默认不按时间或数量自动删除。
- 保留纯文本、Markdown、RTF/HTML、图片、PDF、文件引用及可物化的自定义剪贴板格式，支持多个剪贴板项目。复制图片文件时解析文件引用并保存图像字节，粘贴时提供图片表示。
- 本地 HTML 设置与历史页面支持搜索、格式筛选、分页、预览、复制、移到第1条和删除历史索引。
- “移到第1条”将选中记录插入普通历史的第一位，其他记录顺移。后续新复制会排在它前面，粘贴保持历史顺序。
- 纯文本优先使用 Unicode 输入；其他格式使用临时剪贴板与串行队列，提供等待参数。
- 暂停监听、权限诊断、快捷键冲突提示、按前台应用释放快捷键。
- 历史保存在本机，无云同步或遥测；管理页面不执行剪贴板中的HTML。
- 可开启钉钉文档图片自动补全：后台读取所复制富文本中的HTTPS钉钉图片链接，保存实际图像，提供自包含HTML与RTFD附件。全新安装默认关闭，可在“更多设置与诊断”开启；也可对单条记录点击“补全钉钉图片”。

Markdown 保留剪贴板中提供的源码和原始字节。常见图片文件会保存PNG图像数据。其他文件保存引用，移动或删除源文件可能导致旧记录失效。旧版仅存引用的图片需要原文件仍可访问才能补读。

## 开发者：从源码构建

需要 macOS 和 Swift 6 工具链（Xcode 或 Command Line Tools），系统自带 SQLite，无第三方包依赖。

如果没有安装开发工具，先在终端执行下列命令，并在系统安装窗口完成安装（已有合适工具链可跳过）：

```sh
xcode-select --install
```

工具安装完成后，再执行：

```sh
git clone https://github.com/lrc839-tech/ClipFlow.git
cd ClipFlow
./scripts/test.sh
./scripts/build.sh
```

构建脚本会安装到 `~/Applications/ClipFlow.app`，并生成 `dist/ClipFlow-0.5.zip`。脚本使用本机缓存目录构建和签名，避免文件提供方目录附加 Finder 元数据导致签名失效。

App 使用临时签名，未做 Developer ID 签名或公证。当前实际测试环境为 Apple Silicon、macOS 27.0.1、Swift 6.4 / Command Line Tools。包声明最低 macOS 14，不代表已验证所有系统版本或 Intel Mac。

### 输入权限

1. 打开安装位置的 ClipFlow：DMG 安装通常为 `/Applications/ClipFlow.app`，源码脚本安装为 `~/Applications/ClipFlow.app`。
2. 到系统设置 → 隐私与安全性 → 辅助功能（部分系统显示“设备控制和数据访问”），添加并启用该实际安装副本。
3. 退出重开，或点击历史页“重试注册”，确认权限就绪和快捷键注册状态。

重新构建会改变临时签名。旧条目即使显示开启，也可能不匹配新二进制；需要移除旧条目并重新添加当前 App。不要修改 TCC 数据库或关闭系统安全保护。

未取得输入权限时不占用全局快捷键，历史查看和复制按钮仍可使用。

### 菜单、快捷键与历史

CF菜单保留设置入口、权限与接管状态、Command/Option模式、暂停监听和12条历史。其他操作收进设置中的“更多设置与诊断”。菜单点选记录后，所选内容保留在系统剪贴板，后续Command+V继续使用它。期间发生用户新复制时，新复制优先保留。


`Command+1` 对应当前第一槽，依次到 `Command+=` 的第12槽。设置中的“移到第1条”只调整普通排序，新复制继续排在前面。升级到0.4时，旧版固定置顶转换成普通排序，保留升级时的显示顺序。

Command 模式会占用浏览器切标签、缩放等同组合功能。历史页顶部可释放全部快捷键、切换 Option，或配置按应用排除。排除应用进入前台后注销12键，切回允许应用后重新注册；应用切换通知存在短暂处理间隔。

系统保留组合、安全输入或其他全局工具可能阻止接管，不能保证在所有软件上无条件优先。暂停历史监听与释放快捷键是两个独立操作。

### 钉钉文档图片补全

在“设置 → 更多设置与诊断”开启“自动补全图片”。随后复制或剪切钉钉文档中的图文，等待历史行显示“已保存N张图片”，再通过菜单、快捷键或历史页复制粘贴。单张且无文字时提供PNG；图文混排提供RTFD附件与内嵌图片的HTML，文字顺序和基本格式保留。各软件对这两种格式的支持不同，完整排版及你实际使用的目标编辑器仍需实测。

补全队列独立于普通收录与粘贴。正在补全的记录会提示稍候；其他记录照常处理。结果作为原历史的附属数据保存，不改变原始指纹、复制时间或排序，也不覆盖当前系统剪贴板；需要选择该历史后粘贴。原始内容保留，失败可重试；链接过期或需登录时，请回钉钉重新复制。当前只支持HTTPS `dingtalk.com`及其子域图片，最多12张，单张下载8MiB、合计PNG24MiB、输出快照64MiB；不支持任意网页图片抓取。

开启后将向这些钉钉地址发起图片下载请求，关闭仅停止后续自动收录触发的补全，已排队任务可能继续完成。请求不使用浏览器Cookie或凭据，不采集遥测。源码、公开日志与发布包不包含你的图片、原始历史或临时签名链接。图片补全需要网络，完成并保存后可离线读取。

## 数据与隐私

| 内容 | 本机路径 |
|---|---|
| 历史索引 | `~/Library/Application Support/ClipFlow/history.sqlite3` |
| 二进制内容 | `~/Library/Application Support/ClipFlow/blobs/` |
| 诊断摘要 | `~/Library/Logs/ClipFlow/diagnostics.json` |

历史目录权限0700，主数据库和新写 blob 为0600；没有应用级加密。备份应保持数据库和 blob 一致，运行中的 SQLite 还可能有 WAL 文件。

已识别的敏感剪贴板标记、文件承诺及超过64 MiB的快照会拒绝收录；无法可靠识别未标记的密码。50ms轮询也无法追回两次采样之间已被覆盖的复制。

删除目前只移除历史索引，blob和SQLite空闲页仍可能保留，不是安全擦除。启动时不重复导入现有系统剪贴板；恢复监听时也不补存暂停期间的内容。

本仓库排除了剪贴板数据库、blob、原始诊断日志、测试输出、构建缓存和本机安装包。阶段文档引用的 `output/` 证据仅保留在开发机器上，不随仓库公开。

2026-11-11开发机回归已运行 **71项测试、16个测试套件**。当前验证结果见[0.5剪切与钉钉图片补全](docs/v0.5-dingtalk-images.md)与[0.4修改记录](docs/v0.4-menu-images.md)。测试使用隔离临时数据库和具名系统剪贴板，不读取或修改用户的 general 剪贴板。

| 验证项 | 已取得的证据 / 尚存边界 |
|---|---|
| 持久化 | 真实应用重开、隔离进程 SIGKILL 提交前后恢复、schema迁移及原始多格式字节检查通过；系统重启仍待手工测试 |
| Command注册 | 当前固定版本授权恢复后，12键实际注册成功；独立Carbon实验验证占用冲突与释放 |
| Command实键 | Target中1/2/3三次按所选记录逐项接收、焦点正确；严格固定CBA与连续压力验收尚未通过 |
| 原Option测试 | 12键实键匹配通过；两轮各90次发送与接收映射匹配，但各有两组预设123变成132，根因尚未确定 |
| 格式与管理 | 多格式存储、Markdown原字节、双文件引用结构、历史页面和排序迁移已验证；不代表各目标软件保真验收通过 |
| 待验收 | 完整Command12键、持续高速粘贴、Edge冲突与释放、Finder双文件真实复制、混合格式队列、多应用兼容、屏幕可见延迟 |

事件状态 `posted-unconfirmed` 只代表已发布输入事件。没有通用的目标应用消费回执，等待参数是估计策略；仅检查前台进程，无法覆盖同一应用内所有窗口/输入框变化。

手工验证请使用独立测试输入区和测试目录。完整步骤与限制见[手工验收](docs/manual-acceptance.md)和[0.3 Command模式记录](docs/v0.3-command-mode.md)。未通过项不会因为发布源码而标为完成。

## 开发目录

- `Sources/ClipFlowCore`：热键、快照、监听、FIFO、持久化与粘贴服务。
- `Sources/ClipFlowApp`：正式菜单栏服务和本地历史页面。
- `Sources/ClipFlowProbe`：早期固定槽位 M0 原型，使用 Option 快捷键。
- `Sources/ClipFlowTarget`：独立输入接收窗口，日志保留内容摘要，不保留输入明文。
- `Tests/ClipFlowCoreTests`：核心自动化测试。
- `scripts`：构建、测试与需显式运行的实验脚本。

制作DMG时可复用已经构建并验签的App，不重新构建或改签名：

```sh
python3 scripts/package_dmg.py --app "$HOME/Applications/ClipFlow.app"
```

输出DMG与`SHA256SUMS.txt`到`dist/`；安装说明从`docs/INSTALL.md`同步嵌入。此脚本只打包App、说明和生成的公开元数据，不复制历史、用户配置或日志。

```sh
# 隔离临时数据库中的真实崩溃恢复实验
python3 scripts/test_crash.py
# 构建早期 M0 Probe 和 Target（与当前 App 分开）
./scripts/build.sh m0
```

`test_general.sh`、`test_external_copy.sh` 等实验会使用真实 general 剪贴板；请先阅读脚本说明，不能放入日常自动构建。M0 Probe 和当前 App 不应同时占用相同组合。
