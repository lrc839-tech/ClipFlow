# M0 实际验证记录

测试日期：2026-11-05（Asia/Shanghai）。结论：**M0 最小可行性验证通过，进入 M1**；大样本连续输入、多应用保真及屏幕可见延迟未完成，不能当作产品验收通过。

## 已完成

- 在原工作区中新建 `ClipFlow` 项目，保留原需求文件，初始化本地 Git 仓库，无远程发布。
- Swift + AppKit 菜单栏最小原型；12 个固定实验槽位、Carbon 独占注册、FIFO、Unicode / 临时剪贴板两种文本实验路径。
- 独立目标进程，记录实际接收回调、焦点状态和内容散列，不写输入明文。
- 多项目原始类型快照、SHA-256 指纹、64MiB 保留数据限制、已识别敏感类型与 file promises 拒绝。
- 基于 changeCount 的最佳努力恢复，后续复制优先，含首写失败后的可控恢复路径。
- 本机缓存构建、临时签名验证、本地安装、ZIP 打包与 CLT 可运行的测试脚本。

上述是 M0 实验组件，不代表已经完成文本历史、多格式历史或完整产品。

## 当前限制与阶段门槛

M0没有实现历史监听、去重置顶、SQLite / blob 持久化、应用与系统重启恢复、真实 Finder 复制、混合多格式队列或完整管理界面。T01～T13 均未被整体标为通过；只有其底层组件、单组实键输入和部分诊断路径有证据。后续M1实现另行记录。

已核对一组物理 Option+123 的严格 CBA 与目标进程结果，以及真实系统剪贴板非文本往返，因此建议并已进入 M1。实键合成自动化失败已保留，不用“代码调用成功”替代它。进入 M1 后实现和验收文本历史，M1 文本类验收之前不进入 M2。

下一步：M1完成真实监听、复制去重排序、SQLite+blob持久化、12键与串行粘贴，再执行正常重开/实际崩溃恢复、人工文本验收和扩样速度测试。M1设计与数据安全方案见 `M0-design.md`。
