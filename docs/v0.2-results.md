# ClipFlow 0.2：多格式、Markdown与历史管理

2026-11-05。根据本轮追加要求扩展格式和管理功能。此前连续输入测试的前段次序差异仍未解决，未把M1整体验收或M2/M3全阶段标为通过。

## 已实现

- 接收可物化的原始剪贴板类型、多项目和顺序：纯文本、RTF/HTML、图片、PDF、文件引用、自定义类型。
- Markdown：支持 `net.daringfireball.markdown`、`public.markdown`、`text/markdown`；保留原始字节，向普通输入框复制时补充UTF8文本表示。普通文本中的Markdown原样保留。不会声称可从已渲染网页还原原始Markdown源码。
- 图片/富文本/PDF/文件走完整系统剪贴板路径；短纯文本保留快速Unicode路径。串行队列和新复制优先的恢复保护继续使用，等待参数仍是估计，没有目标完成回执。
- App内本地HTML管理页面：搜索摘要/文件名/类型标识、类型筛选、每页50条、内容预览、图片/PDF缩略图、复制、置顶/取消置顶、逻辑删除。无HTTP服务器，页面禁用网络请求，不执行剪贴板HTML。
- 置顶持久化：最后置顶的排在最前，所有置顶条目先占快捷键槽位；其后按复制时间排列。超过12个置顶时仅前12个占槽。取消置顶后回到正常复制顺序；重复复制不会解除置顶，粘贴不改变顺序。
- 数据库schema1自动迁移schema2。升级前先备份现有21条记录及blobs到本机 `~/Library/Application Support/ClipFlow-Backups/`，具体路径见 `output/v2/backup.json`。

## 当前限制及手工验收

1. 新版签名已改变：在系统设置“设备控制和数据访问/辅助功能”移除旧ClipFlow条目，再添加 `~/Applications/ClipFlow.app` 并启用，退出重开。页面查看、置顶和复制按钮不需要发键权限；全局快捷粘贴需要。
2. 手工复制一张真实截图，在历史中点复制，到图片支持的应用Command+V；再测试Option快捷粘贴。PNG原始数据及缩略图已验证，真实目标渲染/全局混合粘贴未全面验证。
3. Finder选择两个测试文件Command+C，历史应是一条含两个项目的文件记录；复制该记录后到空测试文件夹Command+V，核对内容及源文件仍在。移动/删除源文件后应提示引用失效。文件只保存引用，不备份本体。
4. Markdown用含标题、列表、代码块、链接及中文的源文本测试复制/粘贴，核对源码完全一致。富文本网页不会自动转成Markdown。
5. 文件承诺、未物化提供者、未标记密码、安全作用域续权不能声称支持；64MiB是保留数据上限，同步提供者仍可能阻塞。自定义类型只能保留可读取字节，目标应用是否识别取决于其协议。
6. 搜索针对文本前4096字节、文件名和类型标识，预览最多50000字符，并非无限长正文全文索引。每页只加载摘要，图片按需生成缩略图。删除是索引删除，blob与SQLite空闲页暂保留。
7. 真实系统重启、此前两组132次序差异、混合格式粘贴成功率和屏幕可见延迟仍待验证。
