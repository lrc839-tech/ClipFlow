# M1 文本 MVP：实际状态

2026-11-05（Asia/Shanghai）。状态：**文本MVP已实现，42项核心自动化通过；实际App的12键与持久化已验证，固定30组三连仍未通过，前段次序差异待定位。M2～M3未进入。**

## 本阶段设计和实际实现

- Carbon独占注册12个Option组合，失败显示组合与返回码。无需输入监控，不偷偷改用全键监听。
- 默认50ms真实定时监听。启动/恢复只建立剪贴板基线；单项目文本保留全部可物化原始表示，图片/文件文本fallback不误收为普通文本。敏感标记、文件承诺、超过64MiB、不可读数据整体拒绝。
- 捕获、落库和粘贴在同一FIFO中排序。快捷键到达时先检查未观察的复制，执行临时覆盖前再检查；后续复制排在其因果位置，不能把已排队槽位内容换掉。
- 原始项目/类型/字节指纹去重；重复复制保持UUID、更新单调排序。粘贴不更新复制时间、顺序或记录。
- SQLite WAL/FULL维护索引、顺序及JSON文件引用描述；blob按SHA256命名，原子写入并同步文件/目录后才提交索引。无按时间或数量自动清理。
- 启动校验数据库及最近12条的blob长度和散列；损坏保留原文件、停止使用旧槽并显示诊断。不是启动时扫描全部无限历史。
- 普通短文本直接发Unicode事件，超过2048 UTF16单元或过长组合字符预先转纯文本剪贴板模式。两种路径都拒绝安全输入及前台进程改变；剪贴板模式保留用户后续复制，仍无原子CAS或目标消费ACK。
- 关窗继续菜单栏常驻；正常退出先停止监听并排空已接收任务。启停、文本模式、150/300/500ms等待、存储占用、权限检查和诊断已有最小界面。搜索、删除清空界面、开机启动、排除应用配置界面留待M3。
