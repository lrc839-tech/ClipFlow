# 0.5 剪切与钉钉图片补全

2026-11-11，开发预览。

## 实际实现

- 收录依据系统剪贴板变化，无须监听Command+C。Command+X剪切，只要来源写入剪贴板，同样进入历史。
- 可选自动补全钉钉图文，新安装默认关闭。设置折叠区可开启；已有HTML记录可手动点“补全钉钉图片”。用户本机按其明确选择开启。
- 从复制的HTML中提取HTTPS钉钉图片地址，临时无Cookie会话下载；重定向继续检查来源。仅支持`dingtalk.com`及其子域，不读取浏览器登录状态。错误消息不包含签名链接或原文。
- 图片校验和PNG转换后，单张无文字输出PNG；混排输出RTFD图片附件、内嵌data URI的HTML以及文本。清除脚本、外部资源和不安全样式，HTML导入前用占位符替换图片，防止系统导入器自行联网。
- 图像解码使用后台任务，下载队列独立于收录/粘贴FIFO；最多8个待补全任务。正在补全且无已保存结果的记录，粘贴时提示等待，其他记录可继续使用。
- schema4新增附属结果索引，原始历史和指纹保留。异步结果不调整排序，不覆盖当前剪贴板，不恢复已删除的记录。准备好的图文由菜单、快捷键和历史页复制统一使用。
- 最多12张图片，单张下载8MiB，合计PNG24MiB，输出全部表示64MiB，单图解码像素缓冲上限256MiB。失败保留原始记录，可重试；链接过期需重新复制。

## 已测试

- 71项自动化测试、16个套件通过。包含真实AppKit剪切动作、剪切后入库与重开、三图文字顺序、RTFD实际附件接收、单图PNG、重复链接只下载一次、无效资源/超限/不支持来源拒绝、内容清理、旧schema迁移、附属结果重开、延迟结果不复活删除记录、附属数据损坏不损坏原始记录。
- 模拟图片任务仍在等待时，独立粘贴队列120条请求全部按顺序完成。这验证队列独立性，不是跨应用屏幕延迟测量。
- 在独立Target实际执行Command+X，选中文本被删除；正在运行的0.4监听器将该已知测试文本保存为最新历史。未监听Command+C也可捕获剪切。
- 对用户实际复制的钉钉三图HTML完整下载、转换、隔离入库后重开，再写入具名系统剪贴板。原始快照保持，三张图片均作为NSTextView附件收到，接收文字与准备结果一致，输出共2,280,993字节。
- 隔离数据库两次真实SIGKILL、三次重开检查通过，提交前后身份、指纹、顺序保持。
- 0.5 release构建签名校验通过并安装，schema4迁移后原245条记录的身份、指纹、复制时间、排序及旧置顶字段逐项一致；更新前保留完整历史与旧App备份。
- 实际设置页开启自动补全开关；对已有钉钉记录点补全，界面显示已保存3张图片。经实际历史页“复制”，在独立Target按Command+V收到3个图片附件，再次Command+V共6个附件。这条路径不需要ClipFlow自动发键权限。
- 用户重加固定0.5的辅助功能授权后，退出重开确认AX与事件发布均已授权，Command全局12键注册成功；菜单自动直贴和全局快捷键实际接收尚需独立验收。

本机证据保存在`output/dingtalk-images/`，不公开原始HTML、图像、临时链接和用户历史。`scripts/check_dingtalk_images.swift`可在显式提供本地私有快照时复验，只输出结果元数据，不读取general剪贴板。

## 验证边界与下一阶段

自动化和实际样本证明已取得图像字节并能通过原生富文本格式接收；未证明钉钉、微信、Word、浏览器全部编辑器支持自包含HTML/RTFD，也不保证原文复杂排版完全一致。只粘贴到纯文本框仍无法显示图片。

已验证开关状态、已有记录补全、历史页选中复制及重复Command+V；真实钉钉新复制触发的自动补全仍需实际工作流验证，输入权限需按当前二进制重新核对。菜单直贴、完整12键和连续高速跨应用验收仍需分别验证。

手工测试建议：在钉钉测试文档复制“文字—图片—文字—图片”，等历史显示“已保存2张图片”，通过历史复制到目标应用空白草稿，确认两图、文字顺序及再次Command+V；断网重开ClipFlow，再复制同条历史，确认无需访问临时链接。不要发送草稿。若提示链接过期，重新复制后重试。
