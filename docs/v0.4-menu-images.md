# 0.4 菜单、图片与排序修改

2026-11-10。

## 实现

- CF菜单保留设置入口、输入权限状态、快捷键接管状态、Command/Option模式、暂停监听和12条历史。粘贴方式、等待参数、授权入口、存储、重新校验和退出放进设置。
- “打开历史与诊断”更名“设置”。设置窗口中保留历史管理，增加“更多设置与诊断”折叠区。
- 菜单条目绑定历史UUID，排队期间发生新复制时，选中的记录仍由UUID确定。记录选择后先更新系统剪贴板，再向菜单打开时的目标应用发送粘贴。成功后保留选择，供下一次Command+V使用。期间发生外部新复制时保留新复制。
- 菜单直贴独立于全局快捷键开关和应用排除。输入权限和目标前台进程检查仍生效。缺少可用目标时，选择内容仍保留在剪贴板供手动粘贴。
- 图片文件引用在读取时解析为路径，并保存完整尺寸PNG。旧图片仅存引用时，在源文件仍可访问的情况下补读。图片发送时提供图像表示，移除同一图片项目中的文件名文字与文件URL表示。
- “置顶”改成“移到第1条”，调整普通排序。后续新复制进入第一位，原条目随其他历史向下移动。粘贴维持历史顺序。
- SQLite升级schema3，旧版固定置顶先按旧显示顺序转成普通排序，清除固定置顶状态。保留记录身份、指纹、复制时间和原始数据引用。

图片引用解析使用Foundation的filePathURL，图片读取通过系统图像接口验证。[Apple文件引用说明](https://developer.apple.com/documentation/foundation/nsurl/filepathurl)与[系统剪贴板图像接口](https://developer.apple.com/documentation/appkit/nsimage/init(pasteboard:))。

## 已验证

- 60项测试、13个套件通过。新增回归覆盖图片文件引用加文件名的输入、PNG出站可被NSImage读取、源图片删除后的持久化恢复、纯文件名文字保持、失效图片引用拒绝、菜单保留剪贴板与新复制优先、普通排序和旧固定置顶迁移。
- 两次真实SIGKILL与三次重开检查通过，覆盖提交后与提交前的数据库恢复。
- 开发机191条历史已备份。对独立备份副本执行schema3迁移，全部191条的id、fingerprint、copied_at、sort_index、pinned_rank保持一致，最近12条数据验证通过。该副本原固定置顶数为0，带固定置顶的迁移由专门回归测试覆盖。
- 用户报告的旧图片记录已在具名系统剪贴板中恢复为可读取的PNG，输出没有文件名文本。验证只在本机进行，图像和原始历史未加入仓库。
- 0.4 release构建与签名校验通过，已安装到本机原位置。旧进程窗口控制超时后使用SIGTERM停止，更新前已保留完整历史和旧App备份。新进程实际启动，全部原191条记录身份、指纹和复制时间保持。
- 实际设置页验证“更多设置与诊断”的全部入口可见，存储统计正常执行。通过“移到第1条”把问题图片移到第一槽。
- 从实际历史页复制问题图片，在独立Target中两次Command+V，均得到图像附件，最终为两个图像附件，接收摘要匹配两个对象替换符，未得到文件名文字。
- 在Finder中重新Command+C复制同一图片文件，新版实际收录为带PNG表示的图片记录，成为第1槽，先前移动的记录下移到第2槽。原191条保留，另新增1条带图像数据的记录，共192条，固定置顶数为0。对应本机证据为`actual-image-copy-and-repeat-paste.json`及`finder-copy-and-normal-order.json`。

证据仅在开发机的`output/v0.4/`下保存，公开仓库不包含原始诊断和历史数据。
