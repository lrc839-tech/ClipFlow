# 人工验收：逐项记录，不以计划代替通过

只在测试输入区、测试文件夹使用夹具；不要在聊天发送按钮、支付、密码或生产业务输入框测试自动粘贴。M1代码与自动化见 `M1-results.md`；本表的待测项没有因给出步骤而通过。

## 启动与权限

1. 退出M0 Probe、旧Hammerspoon Option脚本等，只运行 `~/Applications/ClipFlow.app`。
2. 系统设置→隐私与安全→设备控制和数据访问（旧系统“辅助功能”），添加当前App并启用。不要求输入监控，不修改TCC数据库或关闭系统防护。
3. 退出重开ClipFlow；诊断应为12/12、AX=true、事件发布=true。重新构建后若仍拒绝，移除旧授权再添加当前副本。
4. 打开 `~/Applications/ClipFlow M0/ClipFlowTarget.app`。**必须手工用鼠标点击其白色输入区**，再按键；回聊天选择答案会将焦点移回聊天，不能代替目标输入框。

## 文本验收

| 编号 | 操作 | 严格通过标准 |
|---|---|---|
| T01 | 在任意测试编辑器逐次复制A、B、C，每次确认已收录 | ClipFlow最近三条C/B/A，不能漏或重复 |
| T02 | 清空Target后实际持续按住Option，快速按123，松开 | 只得到CBA；无窗口弹起、无特殊符号、无丢键或串位；再做至少30组扩大样本 |
| T03 | 先在不足4条时按Option4，之后复制A～L等12个明确不同夹具，再按1～9、0、-、= | 空槽有可理解诊断且不发输入；12槽与界面顺序逐一对应 |
| T04 | 记录界面顺序，按Option3，再检查 | 全部ID/顺序与复制时间不因粘贴提升 |
| T05 | 复制历史已有内容 | 沿用同一记录并置顶，不增加相同指纹记录；预览相同但格式不同可能保留两条，符合原始数据指纹定义 |
| T06 | 正常退出重开，再在方便时重启macOS并手工打开ClipFlow | 顺序/内容保持，12键重新注册；开机启动尚未实现，重启后需要手工开App |
| T11 | 选临时剪贴板模式、500ms等待，粘贴发出后在另一测试编辑器复制明确新文本 | 最后系统剪贴板保留新文本；对应新内容收录一次，旧快照不得覆盖；记录实际目标与操作时序 |
| T12 | 暂时关闭本App输入授权并重启App，尝试粘贴；再恢复。另用旧热键工具制造一次指定冲突 | 权限拒绝时不改系统剪贴板、不发输入并有错误；冲突有具体组合/返回码与恢复指引 |
| T13 | 退出重开，检查历史和数据目录；自动化崩溃夹具另由test_crash.py覆盖 | 已提交记录不丢，引用文件一致；损坏要显示错误，不能静默变成空历史 |

Unicode兼容性：把ASCII、中文、Emoji（含组合Emoji）、换行、长文本分别在TextEdit、浏览器、IDE、聊天应用的未发送草稿区测试。每个目标应用分别记录Unicode路径与剪贴板路径；任一失败必须记录具体路径，不能列为全应用可用。

连续速度：保留目标为空，按住Option连续输入`123`30遍，中途不清空、不复制其他内容。应得到90个字符且内容等于CBA重复30遍。记录失败数和实际按键节奏，不能用一组1/1宣称稳定100%。带诊断日志的回调延迟不是屏幕可见延迟；真正可见延迟需高帧率录像或明确的屏幕帧观测方案。

## M2尚未开放的验收

T07网页RTF/HTML格式保真、T08截图/图片、T09 Finder两个文件复制到测试目录且源文件仍在、T10文本/图片/文本混合队列，需要M1文本验收通过后再实施和逐项真实测试。M1仅存可物化文本原始类型，不宣称已支持这些粘贴。

## 记录格式

每条填写：日期、macOS版本、目标应用与版本、输入模式、等待参数、夹具、操作节奏、预期、实际、重复次数/失败次数、日志文件。仅记录测试夹具；不要把私人剪贴板内容发到问题日志或分享报告。
